# 53. 通常画面と連携先画面の共通化

## 変更内容

れぞらぶとぐりすぺの両フォークで、次の表示・操作部品を共用する。

| 対象 | 共通部品と利用箇所 |
| --- | --- |
| 続きの読み込み | `MkTimelineLoadMore`。ノート一覧に加え、通知、ページ・ギャラリー、クリップ、チャンネル一覧、連携先ドライブで使用。自動読み込みの設定と画面の表示状態に従う。 |
| ノート本文・CW | `MkNoteText`、`MkNoteCw`。通常ノート、通常の詳細、連携先ノートで使用。絵文字のURLと操作可否は呼び出し元から渡す。 |
| ノート詳細 | `MkNoteDetailedArticle`、`MkNoteDetailedHeader`、`MkNoteInfo`。連携先ノートの詳細にも、通常の詳細と同じヘッダー、余白、日時・公開範囲の表示を使う。 |
| 投稿フォーム | `MkPostFormHeader`、`MkPostFormFields`、`MkPostFormActionBar`。通常と連携先のフォームで、ヘッダー、CW・本文の枠、操作ボタンを共用。入力要素の参照、IME、添付・送信処理は元のフォームが持つ。 |
| チャンネル概要 | `MkChannelOverview`。バナー、説明、統計、センシティブ表示、フォロー・お気に入りの配置を共用。 |
| 通知 | `MkNotificationLayout` に加え、`MkFollowRequestActions` で承認・拒否ボタンを共用。 |
| ドライブ | `MkDriveNavigation`、`MkDriveGrid`。パンくずの枠とファイル・フォルダー一覧の配置・アニメーションを共用。ファイル・フォルダーのセルは従来の共通部品を使う。 |

## 分けて保持する処理

- 取得・送信・削除などのAPI呼び出しは、対象のサーバーと権限に応じて元のコントローラーが実行する。
- 連携先の限定投稿・添付は、権限の再確認と失効時の非表示を維持する。通常のノートキャッシュには入れない。
- 連携先のIDを通常APIへ渡す変換は行わない。
- 相手サーバーが返さない情報や利用できない操作は、この共通化によって新たに利用可能になるわけではない。会話の取得、翻訳、投稿の可否などは各コントローラーの責任範囲に残す。
- DB、連合プロトコル、APIの変更はない。

## 検証

- 自動読み込みON/OFF、明示的な手動指定、非表示・復帰、権限再確認後の再開を検証する。
- フォームの入力参照・キーボード操作と、ピッカーへ渡すクリック対象を検証する。
- 詳細表示、絵文字URLと操作制限、通知の承認・拒否、チャンネル操作の委譲を検証する。
- 既存の限定投稿・通知・ホームの関連テストも実行する。
- 両フォークで変更ファイルのlint、SPDX、locale safetyを確認し、リリースイメージをビルドして反映する。

変更履歴候補: 通常画面と連携先画面で、一覧の読み込み、ノート本文・詳細、投稿フォーム、チャンネル概要、通知操作、ドライブ表示の部品を共通化しました。
