# 参照クリップの解除と限定投稿メニュー

## 操作

- 自分が管理する参照クリップのノートに「クリップから外す」を表示する。
- 解除後は該当する一覧から即座に除き、先行していた取得応答で復活しないようにする。
- 連携先で読める限定投稿に、お気に入り、クリップ追加・新規作成、スレッドミュート、翻訳、通報、投稿者メニューを表示する。
- 連携先の自分の投稿ではピン留めと削除も表示する。チャンネル投稿の削除は既存のチャンネル専用処理を使う。
- 通報フォームは通常の共通コンポーネントを使う。
- 公開・ホーム投稿の通常メニューは維持し、参照クリップの解除だけを追加する。

## 名義と権限

限定投稿の保存・ミュート・通報・ピン留めは、連携した旧アカウントで行う。限定投稿の本文やIDを通常のローカルAPIに渡さない。クリップ追加先は、旧アカウントが所有するクリップ。

専用API gridspace/note-menu と署名付きサーバー間APIを使用する。書き込み時は連携先が閲覧権限、OAuthの操作権限、名義、所有者を検証する。読み取り終了時も認可を再確認し、クリップ一覧の取得には操作権限が必要。ローカル側の管理者権限を相手サーバーに転用しない。

確認ダイアログはメニューを閉じても継続できるが、元のノートを表示していた行が破棄・非表示になったら操作を止める。

## 検証

権限失効、名義の不一致、非所有クリップ、限定投稿の閲覧失効、保存の重複、作成失敗、解除と読み込みの競合、確認中の画面離脱をテストする。SDKはAPI定義から再生成する。
## デプロイ後の確認

コンテナーの正常判定とバージョンだけでなく、認証付きのサーバー間読み取りも確認する。再起動直後に中継の接続が復旧しない場合は、両サーバーで中継Nginxの設定を検証して再読み込みし、再確認する。

```sh
docker compose exec -T gridspace-peer nginx -t </dev/null
docker compose exec -T gridspace-peer nginx -s reload </dev/null
```

本作業では `.31.27` に反映後、クリップ一覧と限定投稿のメニューを再確認した。操作確認で外したノートは元のクリップへ戻し、お気に入りも変更前の状態へ戻した。
