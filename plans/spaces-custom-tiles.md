# スペース 段階4(自作タイル)の実装設計

[spaces-design.md](spaces-design.md) の段階4を、実装できる細かさで書く。枠と `space` API は段階3で作ってあり、[spaces-tiles.md](spaces-tiles.md) にある。

1〜10章は実装する前に書いた設計。実装した結果と、設計と違うところは 11章にある。

## 1. 前提

### 1.1 決まったこと(2026-11-26)

| 項目 | 決定 |
| --- | --- |
| 作って公開できる人 | ローカルの全員。モデレーターは他人のタイルを消せる |
| 外への持ち出し | 受け入れる。置くときの注意も出さない |
| 外部の URL の取得(`space.fetch`) | タイルが読みに行く先のドメインを宣言し、置く人が置くときに許す。取得は本体のサーバーが代わりに行う |
| 作者が書き換えたとき | 置いてあるタイルも新しいコードで動く |

### 1.2 仮に置いた案

決定から導いたものと、設計を進めるために仮に置いたもの。違っていれば直す。

| 項目 | 内容 | 節 |
| --- | --- | --- |
| 許したドメインは広がらない | コードは追従するが、許可は置いたときのまま。作者があとで宣言を足しても、足した先は読めない。ホストか置いた人が許し直す | 5 |
| 追従が届く時 | 次に枠を読み込んだ時。開いている枠を途中で差し替えない | 3.3 |
| タイルを消したとき | 置いてあるタイルは「このタイルは消されました」になる。共有する値は残す | 3.3 |
| 公開の範囲 | 「公開」と「自分だけ」の2つ。自分だけのタイルも、自分では置ける | 3.1 |
| 投稿 | `space.post(text)` は本体の投稿フォームを開くだけ。投稿ボタンは本人が押す | 4 |
| ホストだけが操作できるタイル | 置くときに選べる。サーバーが書き込みを止める | 6 |
| コードの大きさ | 256 KB まで。共有する値の1回の書き込みと同じ歯止め | 3.1 |
| 連合 | しない。タイルの定義はこのサーバーの中だけ | - |

## 2. 全体の構成

```
作成画面(コードを書く、試す、公開する)
   │  spaces/tile-defs/* API
テーブル space_tile_def(タイルの定義: 名前、説明、コード、読みに行く先)
   │  space_tile.defId が指す
置いてあるタイル(段階3と同じ枠で動く。コードだけが定義から来る)
```

段階3からの違いは3つだけ。

- タイルのコードが、本体に入っているものだけでなく、DB の定義からも来る。
- 枠の API に `space.fetch` と `space.post` が増える。
- 置くときに、読みに行く先と「ホストだけが操作できる」を決める。

## 3. データ

### 3.1 テーブル `space_tile_def`(新規)

| 列 | 型 | 中身 |
| --- | --- | --- |
| `id` | id | |
| `userId` | id | 作者。ユーザーを消すと一緒に消える |
| `name` | varchar(100) | 名前 |
| `description` | varchar(1000) | 説明 |
| `code` | text | HTML と JavaScript。256 KB まで |
| `fetchHosts` | varchar(253)[] | 読みに行く先のドメイン。宣言していない先は読めない |
| `visibility` | enum `public` / `private` | 一覧に出すか |
| `updatedAt` | timestamp | コードを書き換えた時 |

作った時刻は `id` から取る。「いいね」や使われた回数は作らない。

### 3.2 テーブル `space_tile` に足す列

| 列 | 型 | 中身 |
| --- | --- | --- |
| `defId` | id、null 可 | 自作タイルの定義。きほんのタイルは null。定義を消すと null になる |
| `allowedHosts` | varchar(253)[] | 置くときに許したドメイン |
| `hostOnly` | boolean | ホストだけが操作できる |

自作タイルの `kind` は `custom` とする。定義が消えたタイルは `kind` が `custom` で `defId` が null になり、それで見分ける。

### 3.3 コードの届け方

- スナップショットとタイルの追加の知らせに、定義の `id`、`name`、`updatedAt`、作者を載せる。コードは載せない。
- コードは `spaces/tile-defs/show` で取る。画面は `id` と `updatedAt` の組で覚えておき、同じものを取り直さない。
- 作者が書き換えても、開いている枠はそのまま動き続ける。入り直す、またはタイルを開き直すと新しいコードになる。
- 「続きをひらく」は `defId`、`allowedHosts`、`hostOnly` も引き継ぐ。

## 4. `space` API に足すもの

| 名前 | 中身 |
| --- | --- |
| `space.fetch(url, options?)` | 外部の URL を GET で読む。返すのは `{ status, contentType, text }`。`options.json` が真なら `json` も返す |
| `space.post(text)` | 本体の投稿フォームを、本文を入れた状態で開く。投稿するかどうかは本人が決める。返り値は無い |
| `space.hostOnly` | このタイルが「ホストだけが操作できる」かどうか |

既にある `space.misskey`、`space.preview`、`space.pickFile`、`space.open` は、自作タイルにもそのまま開ける。持ち出しを受け入れると決めたので、段階3で「手当てが要る」とした `space.preview` の制限は付けない。

### 4.1 `space.fetch` の流れ

1. 枠が本体に頼む。本体は API `spaces/tiles/fetch`(`tileId`、`url`)を呼ぶ。
2. サーバーは、呼んだ人がそのスペースにいること、URL が https であること、ホスト名がそのタイルの `allowedHosts` にあることを確かめる。
3. サーバーが取りに行く。Misskey の外向きの通信と同じ道を使うので、内側のアドレスには届かない。リダイレクトは、移った先も `allowedHosts` にあるときだけ追う。
4. 本文は 1 MB まで、待つのは 10 秒まで。文字として返す。画像などは返さない。

サーバーが取りに行くので、取得先に見えるのはサーバーの IP で、見ている人の IP や Cookie は渡らない。

上限なしの方針に合わせ、回数の制限は API の既定の歯止め(1人あたり)だけにする。同じ URL は 30 秒のあいだサーバーで覚えておき、人数分の取得が重ならないようにする。

## 5. 置くときの許可

- 自作タイルを置くとき、その定義の `fetchHosts` が空でなければ、ドメインの一覧を見せて「これらを読むことを許す」を確かめる。空なら何も出さない。
- 許したドメインは `space_tile.allowedHosts` に入る。許さずに置くこともでき、その場合 `space.fetch` はすべて失敗する。
- 作者があとで `fetchHosts` を足しても、`allowedHosts` は変わらない。タイルの上に「読みに行く先が増えました」を出し、ホストか置いた人が許し直せる(API `spaces/tiles/update`)。
- 作者が `fetchHosts` から外した先は、`allowedHosts` に残っていても読めない(両方にあるものだけ読める)。

## 6. ホストだけが操作できるタイル

- 置くときに選ぶ。ホストはあとから切り替えられる(`spaces/tiles/update`)。
- 真のとき、サーバーはホスト以外の `setShared` と `signal` を捨てる。枠には `space.hostOnly` と `space.isHost` を渡すので、タイルは操作の部品を隠せる。
- きほんのタイルにも効く。きほんのタイルは、操作できない人に部品を隠す対応まではしない(押しても変わらないだけ)。

## 7. API(追加)

| エンドポイント | 中身 | 権限 |
| --- | --- | --- |
| `spaces/tile-defs/create` | 作る | `write:spaces` |
| `spaces/tile-defs/update` | 書き換える。作者だけ | `write:spaces` |
| `spaces/tile-defs/delete` | 消す。作者とモデレーター | `write:spaces` |
| `spaces/tile-defs/show` | コードを含めて1つ返す。自分だけのタイルは、作者と、それが置いてあるスペースにいる人に返す | `read:spaces` |
| `spaces/tile-defs/list` | 公開されているものの一覧。新しい順。コードは含めない | `read:spaces` |
| `spaces/tile-defs/my` | 自分のものの一覧 | `read:spaces` |
| `spaces/tiles/update` | `allowedHosts` と `hostOnly` を変える | `write:spaces` |
| `spaces/tiles/fetch` | 4.1 | `write:spaces` |

`spaces/tiles/add` に `defId`、`allowedHosts`、`hostOnly` を足す。

## 8. 画面

### 8.1 足すページ

| 道 | 中身 |
| --- | --- |
| `/spaces/tiles` | 公開されているタイルの一覧と、自分のタイルの一覧 |
| `/spaces/tiles/new`、`/spaces/tiles/:defId/edit` | 作成画面 |

### 8.2 作成画面

- 左にコード(`MkCodeEditor`)、右に試しに動かす枠。保存しなくても「動かす」で枠を作り直す。
- 試しの枠は、スペースにつながない。共有する値と知らせは画面の中だけで回す。いる人は自分だけ。「もう1人を足す」で枠を2つ並べ、共有が届くことを確かめられる。
- 試しの枠では `space.fetch` は宣言した先にそのまま届く(作者自身の操作なので、許可は聞かない)。
- 新しく作るときは、短い見本(カウンター)を入れておく。`space` API の一覧を横に出す。
- キャンバスの「タイルをつくる」に書いたコード例は、実際の API の形に直す。

### 8.3 置く

- 通話画面の「タイルを足す」に、「きほん」と「みんなのタイル」と「自分のタイル」の3つの見出しを作る。
- 自作タイルの頭には、名前と作者を出す。

## 10. 残る弱いところ(作る前から分かっているもの)

- **自作タイルは、スペースの中で見えるものを外へ出せる**。共有する値、いる人の名前とアイコン、公開されているノートなど。受け入れると決めた。見ている人の IP は、枠が自分を別のサイトへ移動させたときに、そのサイトへ渡る。
- **作者は、置いてあるタイルの中身をいつでも変えられる**。追従すると決めたため。信用できない作者のタイルを置かない、で防ぐ。
- **`space.fetch` は、サーバーを踏み台にした取得になる**。許した先だけ、GET だけ、1 MB までに絞るが、取得先から見ればこのサーバーからの通信になる。
- 自作タイルが重い処理をすると、その人の画面が重くなる。止める仕組みは無く、タイルを片づけるしかない。

## 11. 実装した結果(2026-11-26)

順1〜6をすべて実装した。手元の開発サーバーで動かして確かめた。本番には出していない。

### 11.1 確かめた範囲

| 確かめ方 | 結果 |
| --- | --- |
| 単体テスト(スペース関係) | 55件すべて通過 |
| API とストリーミングの通し(段階4) | 46項目すべて通過 |
| API とストリーミングの通し(段階1〜3) | 53項目すべて通過 |
| ブラウザ2つでの通し(段階4) | 30項目すべて通過 |

| migration | 当てる、戻す、当て直すが通る。`check-migrations` は差分なし |
| 出口チェック | Lint: PASS、SPDX: PASS、Locale safety: PASS |

ブラウザでは、作成画面でつくる、2人でためす、保存する、一覧と詳細、スペースに置く、共有が届く、ホストだけ、置くときの許可、許し直し、`space.fetch`、`space.post`、作者が書き換えて入り直す、定義を消す、を通した。

確かめていないもの:

- Chromium 以外のブラウザ、スマホの幅。
- 本番の構成での `space.fetch`。手元では `example.com` と `example.org` を読んだ。
- 大きいコード(256 KB 近く)、重い処理をするタイル。
- モデレーター(管理者でない)による削除。管理者では確かめた。

### 11.2 設計と違うところ

- **「ホストだけが操作できる」は、置くときではなく、置いたあとにタイルの見出しの鍵のボタンで切り替える**。API は置くときの指定も受ける。置けるのも切り替えられるのもホストだけ。
- **置く画面は、ダイアログではなくメニュー**。「タイルを置く」のメニューに、きほん・自分のタイル・みんなのタイルを並べた。出るのは新しい順に30件ずつ。それより古いものは、いまは画面から置けない。
- **`spaces/tiles/fetch` は `defId` でも呼べる**。作者が作成画面の試しの枠から読むため。作者本人だけが、自分の宣言した先を読める。保存する前は試せない。
- **許せるのは、定義が宣言している先だけ**。置くときも許し直すときも、宣言に無い先はサーバーが落とす。
- **保存すると、作成画面は作り直される**。URL が書き換えのものに変わり、試しの枠の値は最初に戻る。
- **枠の部品を分けた**。枠との通信だけを受け持つ `MkSpaceTileFrame` を作り、スペースの中(`MkSpaceTile`)と試しの枠(`MkSpaceTilePreview`)の両方で使う。
- キャンバスの「タイルをつくる」のコード例は、まだ直していない。

### 11.3 レビューで直したこと

Codex と、API・画面それぞれのレビュー用エージェントにかけた。

- `space.fetch` の覚えておく結果を、許した先ごとに分けた。分けないと、広く許したタイルがリダイレクト先で読んだ結果を、狭く許したタイルにも返していた。
- 「ホストだけ」の切り替えが重なったとき、Redis が DB とずれないよう、DB の値を読み直してから Redis に写すようにした。
- ホストだけにしたタイルで、ほかの人が押すと自分の画面だけ値が変わっていた。本体がいまの値を送り返して元に戻す。Play のタイルも同じく止めた。
- 試しの枠で、相手の枠がつながる前に書いた値が届かなかった。値を持っておき、つながったときに渡す。
- `space.post` の本文が、投稿フォームの下書きで置き換わることがあった。下書きと別のフォームを開くようにした。
- 許し直しの API が、宣言に無い先もそのまま保存していた。
- 一覧のページが、取得に失敗すると読み込み中のままになっていた。

### 11.4 残っている弱いところ

- **内側のアドレスを止める仕組みは、Misskey の設定に従う**。`allowedPrivateNetworks` に例外を入れている、内側に届くプロキシを通している、開発用の設定で動かしている、のどれかだと、自作タイルから内側に届きうる。本番の設定を確かめる必要がある。
- **作者が定義を書き換えた・消したことは、開いている画面に届かない**。入り直すまで、読みに行く先が増えた知らせは出ず、消されたタイルも動き続ける。
- **作る・書き換える API に、回数の歯止めを付けていない**。上限を設けない方針による。1回のコードは 256 KB まで。
- モデレーターが他人のタイルを消しても、モデレーションログには残らない。
- API の通しの確認は手元のスクリプトで、リポジトリの e2e テストにはしていない。
- 10章の弱いところ(持ち出し、置いたあとの書き換え、サーバーを踏み台にした取得、重いタイル)は、そのまま残っている。
