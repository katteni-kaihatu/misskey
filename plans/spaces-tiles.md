[spaces-design.md](spaces-design.md) の段階3を、実装できる細かさで書く。段階1と2の実装は [spaces-implementation.md](spaces-implementation.md) にある。

この文書はまだ実装していない設計で、書いてある仕組みは動かして確かめたものではない。

## 1. 前提

### 1.1 決まったこと(2026-11-26)

| 項目 | 決定 |
| --- | --- |
| 作るタイル | 9種。ノート、画像、投票、やること、らくがき、メモ、リンク、Play、タイマー |
| タイルの作り | 自作タイルと同じ仕組み。隔離した枠の中で、HTML と JavaScript が `space` API を使って動く |
| Play だけの例外 | タイルの中で Play を動かす。Play は AiScript で動くので、枠ではなく本体が直接描く |

## 2. 全体の構成

```
タイル(枠の中の HTML と JS)
   │  space API(枠と本体のあいだの通信)
本体(Misskey の画面)
   │  ストリーミングのチャンネル space
Misskey のサーバー ── Redis(いまの値) ── DB(保存)
```

- タイルは自分では通信しない。外とのやり取りはすべて本体を通る。
- 本体は、タイルから受けた書き込みをすぐ手元の表示に反映し、サーバーへ送る。
- サーバーは届いた順に番号を振って保存し、スペースの全員に配る。計算はしない。
- 途中から入った人には、入るときに全タイルのいまの値を渡す。

## 3. データ

### 3.1 テーブル `space_tile`(新規)

| 列 | 型 | 内容 |
| --- | --- | --- |
| `id` | id | |
| `spaceId` | id、索引あり、スペース削除で一緒に消す | 置いてあるスペース |
| `kind` | varchar(64) | タイルの種類。きほんのタイルは `note`、`image`、`poll`、`todo`、`draw`、`memo`、`link`、`play`、`timer` |
| `creatorId` | id | 置いた人 |
| `position` | integer | 並び順 |
| `shared` | jsonb | 共有する値の保存。キー → 値 |

段階4で自作タイルを足すときは、`kind` の代わりにタイルの定義(コード)を指す列を足す。

### 3.2 テーブル `space` に足す列

| 列 | 型 | 内容 |
| --- | --- | --- |
| `tilePlacement` | enum `everyone` / `host` | タイルを置ける人。既定は `everyone` |
| `continuedFromId` | id、null あり | 「続きをひらく」の元のスペース |

### 3.3 Redis

| キー | 型 | 内容 |
| --- | --- | --- |
| `space:{id}:tile:{tileId}:shared` | hash | キー → 値(JSON)。いまの値の正 |
| `space:{id}:rev` | 数 | 書き込みに振る通し番号 |
| `space:{id}:dirty` | set | DB に写していないタイルの ID |

- 書き込みのたびに DB を更新すると、らくがきのように回数が多いタイルで重くなる。そのため、開いている間の正は Redis に置く。
- DB へは、5分ごとの定期ジョブと、閉じるときに写す。
- Redis の中身が消えた場合は、DB の最後の保存から戻す。最長で5分ぶん巻き戻る。

## 4. サーバーとのやり取り

### 4.1 API(追加)

| エンドポイント | できる人 | すること |
| --- | --- | --- |
| `spaces/tiles/add` | 置ける人(3.2 の `tilePlacement`) | タイルを置く。種類を渡す |
| `spaces/tiles/remove` | 置いた本人、またはホスト | 片づける |
| `spaces/tiles/move` | 置ける人 | 並び順を変える |

- 置く・片づける・並べ替えるは、権限の確認と失敗の返事が要るので API にする。
- `spaces/update` に `tilePlacement` を足す。
- `spaces/create` に `continueFromId` を足す(9)。

### 4.2 ストリーミング(チャンネル `space` に足す)

サーバーから届くもの。

| 名前 | 中身 | いつ |
| --- | --- | --- |
| `snapshot`(足す) | タイルの一覧、各タイルの共有する値、担当のユーザー ID | つないだ直後 |
| `tileAdded` | タイル | だれかが置いた |
| `tileRemoved` | タイルの ID | 片づけた |
| `tilesMoved` | タイルの ID の並び | 並べ替えた |
| `shared` | タイルの ID、キー、値、通し番号、書いた人 | 共有する値が書かれた |
| `signal` | タイルの ID、種類、中身、送った人 | 一時的な知らせ(保存しない) |
| `leader` | ユーザー ID | 担当が替わった |

ブラウザから送るもの。

| 名前 | 中身 | すること |
| --- | --- | --- |
| `setShared` | タイルの ID、キー、値 | 保存して `shared` を配る |
| `signal` | タイルの ID、種類、中身 | 保存せずに `signal` を配る |

### 4.3 書き込みの規則

- サーバーは届いた順に通し番号を振る。同じキーに2人が同時に書いたら、後から届いたほうが残る。
- 本体は、自分の書き込みをすぐ手元に反映する。サーバーから番号つきで戻ってきたら、番号の大きいほうを正とする。
- キーは 1〜64 文字、値は JSON にできるものなら何でもよい。1回の書き込みは 256 KB まで。
- 値を `null` にするとキーを消す。
- 人ごとの値(投票の票など)は、キーにユーザー ID を入れて書く(例: `vote:{userId}`)。こうすれば2人の書き込みはぶつからない。

## 5. 担当

タイマーが切れたときのように、全員の手元で同時に起きる出来事は、担当の1人だけが実行する。

- 担当はサーバーが決める。ホストがスペースにいればホスト。いなければ、いちばん長くいる人。
- 人が入る・出るたびにサーバーが決め直し、替わったら `leader` を配る。
- タイルは `space.isLeader` で、自分が担当かを知る。
- 担当が出来事を実行したら、結果を共有する値に書く(例: `finished: true`)。ほかの人はその値を見て表示を変える。担当が替わる前後で二重に実行されても、同じ値を書くだけなので害が無いように書く。
- 担当の回線が悪い場合の手動の切り替えは作らない。担当がスペースから出れば、自動で次の人に移る。

## 6. 枠と `space` API

### 6.1 枠の作り

タイルは、権限を絞った埋め込み枠(`sandbox="allow-scripts"` の iframe)の中で動かす。

- 枠の中身は、本体が文字列として組み立てて渡す。順番は、通信の制限(下記)、`space` を用意する部分、タイルの HTML と JavaScript。
- 枠は Misskey のページとは別の出どころとして扱われる。Misskey のアクセストークン、保存データ、Cookie には触れない。
- 枠の先頭に通信の制限(Content-Security-Policy)を入れる。スクリプトとスタイルは枠の中に書いたものだけ、画像と音はこのサーバーのファイルだけを読める。それ以外の通信(`fetch` など)はできない。
- 新しいウィンドウを開く、フォームを送る、上のページを移動させる、はどれもできない。リンクを開きたいときは `space.open` を使う(本体が確認を出す)。
- 枠の高さは、中身に合わせて本体が自動で変える。

### 6.2 残る穴

- 枠は、自分自身をほかのサイトへ移動させることができる。このとき URL にデータを載せれば、外へ持ち出せる。ブラウザに止める手段が無い。
- 段階3のタイルは本体が用意したものだけなので、実害は無い。段階4で自作タイルを開けるときに、持ち出せる情報(共有する値、いる人の名前、公開されているデータ)をどこまで許すかを決める。

### 6.3 `space` API(段階3で作る範囲)

| 呼び方 | すること |
| --- | --- |
| `space.shared(key, initial)` | 全員で共有する値。`.get()`、`.set(value)`、`.on(fn)` を持つ |
| `space.mine(key, initial)` | 自分だけの値。使い方は `shared` と同じ。ブラウザの中にだけ保存する |
| `space.send(type, body)` / `space.on(type, fn)` | 保存しない一時的な知らせ。その場にいる人にだけ届く |
| `space.me` | 自分の ID、名前、アイコン |
| `space.members` / `space.onMembers(fn)` | いる人の一覧と、その変化 |
| `space.isHost` | 自分がホストか |
| `space.isLeader` / `space.onLeader(fn)` | 自分が担当か、その変化 |
| `space.misskey(endpoint, params)` | Misskey の公開データを読む。使えるのは `notes/show`、`users/show`、`flash/show` |
| `space.pickFile()` | 本体がドライブの選択画面を出し、選んだファイルの URL と名前を返す |
| `space.preview(url)` | リンクのタイトル、説明、画像を返す(既存のリンクプレビューを使う) |
| `space.open(url)` | 本体が確認を出してから、新しいタブで開く |

- `space.misskey` は、本体がログインなしの立場で代わりに読む。フォロワー限定のノートや自分の通知は読めない。
- `space.fetch`(外部の URL の取得)と `space.postButton`(投稿ボタン)は、9種のタイルが使わないので段階4に回す。
- キャンバスの「タイルをつくる」に書いたコード例は、この表の形に合わせて段階4で直す。

## 7. きほんのタイル 9種

| タイル | できること | 共有する値 | 使う API |
| --- | --- | --- | --- |
| メモ | みんなで1枚の文章を書く | `text` | `shared` |
| 投票 | 選択肢を作り、1人1票で選ぶ。結果がその場で出る | `question`、`choices`、`vote:{userId}` | `shared`、`me` |
| やること | 項目を足し、済んだものに印を付ける | `item:{id}` | `shared` |
| タイマー | 時間を決めて始める。全員に同じ残り時間が出て、切れたら鳴る | `endsAt`、`finished` | `shared`、`isLeader`、`send` |
| らくがき | みんなで1枚に描く。描いている途中の線も見える | `stroke:{id}` | `shared`、`send`(描いている途中の線) |
| 画像 | ドライブの画像を1枚出す | `file` | `shared`、`pickFile` |
| リンク | URL をカードで出す | `url`、`preview` | `shared`、`preview`、`open` |
| ノート | ノートの URL か ID を入れると、そのノートを出す | `noteId` | `shared`、`misskey`、`open` |
| Play | 既存の Misskey Play を置いて、その場で動かす | `flashId` | 本体が直接描く(下記) |

- タイルのコードは `packages/frontend/src/spaces/tiles/` に、種類ごとの HTML ファイルとして置く。
- ノートのタイルは、本文を文字として出す。絵文字や装飾(MFM)は段階3では描かない。全文は `space.open` でノートのページを開いて見る。
- タイマーは、切れる時刻(`endsAt`)を共有する。残り時間は各自の画面で計算して出す。切れたことを書くのは担当だけ。

### 7.1 Play のタイル

- Play は AiScript で動き、Misskey の部品で描く。枠の中では動かせないので、このタイルだけ本体が直接描く。
- いまの Play のページ([flash.vue](../packages/frontend/src/pages/flash/flash.vue))から、動かす部分を部品として切り出して使う。
- Play は各自の画面で別々に動く。押したボタンや入力は、ほかの人には伝わらない。共有するのは「どの Play を置いたか」だけ。
- Play のコードは、もとの Play のページと同じ権限で動く。スペースの値やほかのタイルには触れない。

## 8. 置ける人、操作できる人

- タイルを置けるのは全員。ホストは「ホストだけ」に切り替えられる(`tilePlacement`)。
- 片づけられるのは、置いた本人とホスト。
- タイルの中の操作(投票する、描く など)は、スペースにいる全員ができる。タイルごとの「ホストだけが操作できる」は段階4で足す。

## 9. 続きをひらく

- 閉じたスペースのまとめの画面に、ホストにだけ「続きをひらく」を出す。
- 押すと、ひらく画面が元の名前と設定を入れた状態で開く。
- 新しいスペースには、元のスペースのタイル、並び順、共有する値を写す。チャット、自分だけの値、いた人は引き継がない。
- 元のスペースは変えない。同じスペースから何度でも続きをひらける。
- 続きをひらけるのは、元のスペースのホストだけ。

## 12. 決めること、確かめること

### 決めること

- らくがきが大きくなったときの扱い。線の一覧をそのまま持つので、長く描くと途中参加の人に渡す量が増える。
- タイルに名前を付けられるようにするか(「投票」が2つあるときの見分け)。

### 確かめること

- 枠の中に入れた通信の制限が、主なブラウザで実際に効くか。順3で試す。
- スマホで、枠の中の文字入力やスクロールが引っかからないか。
- Play を部品として切り出したとき、いまの Play のページが変わらず動くか。

## 13. 順1〜3を実装した結果(2026-11-26)

11章の順1〜3(タイルのテーブルと API、共有する値、枠と `space` API、メモのタイル)を実装した。順4以降はまだ作っていない。

### 13.1 設計と違うところ

- タイルのコードは HTML ファイルではなく、文字列を持つ TypeScript のファイルにした(`packages/frontend/src/spaces/tiles/memo.ts`)。読み込みの仕組みを足さずに済むため。
- 枠が読める画像と音は、このサーバーの `/files/` の下だけにした。サーバー全体を許すと、外部の URL を代わりに取りに行く経路(`/proxy/`)を通して、データを外へ送れてしまうため。その結果、いる人のアイコン(`/proxy/` を通る)は枠の中に出せない。投票などでアイコンを出したくなったら、本体が画像を渡す方法を別に作る。
- 自分だけの値の保存先は、アカウントごとに分けた。
- 「タイルを置く」は、通話画面にボタンを仮に置いた。右のタブへの作り直し(順4)はまだ。
- `space.isLeader`、`space.misskey`、`space.pickFile`、`space.preview` はまだ無い。使うタイルを作る順で足す。

### 13.2 設計に無く、足したもの

- 枠の通信の制限に、WebRTC を止める指定を足した。
- 絵文字を作る枠(既存の機能)のメッセージの受け口に、送り元の確認を足した。確認が無いと、タイルの枠から同じ形のメッセージを送って、本人の権限でドライブへのアップロードや絵文字の登録を動かせた。スペース以外の既存のコードに入れた変更はこれだけ。
- 生存確認が途絶えて「いる人」から外された接続からは、タイルに書けないようにした。

### 13.3 残っている弱いところ

- 2つの書き込みがほぼ同時にサーバーに届いたとき、振った番号と保存の順が入れ替わることがある。サーバーを複数のプロセスで動かしている場合にだけ起きる。
- 閉じる処理の最後の保存と書き込みが重なると、その書き込みが保存されないことがある。
- 6.2 の穴(枠が自分自身をほかのサイトへ移動させて、URL にデータを載せる)はそのまま残っている。

### 13.4 確かめた範囲

| 確かめたこと | 方法 | 結果 |
| --- | --- | --- |

## 14. 順4〜9を実装した結果(2026-11-26)

11章の残り(通話画面の作り直し、タイル8種、担当、らくがき、Play、続きをひらく)を実装した。段階3の機能は一通りそろった。

### 14.1 設計と違うところ

- **`space` API に足したもの**: `space.keys(prefix)`(共有する値のキーの一覧)、`space.onShared(fn)`(どのキーが変わっても呼ばれる)、`space.origin`(このサーバーの URL)、`space.t(key)`(タイルの文言)。投票の票ややることの項目のように、キーの数が決まっていないタイルを書くのに要った。
- **タイマーが切れたときの処理**: 担当だけが書く、としていたが、担当がタイマーを画面に出していない(ほかのページを見ている)と切れないままになる。担当が3〜5秒たっても書かなければ、ほかの人が書くようにした。音は、切れた時刻ごとに各自の画面で1回だけ鳴らす(知らせを送る方式はやめた)。
- **投票の票のキー**: `vote:{userId}` ではなく `vote:{投票のID}:{userId}` にした。作り直しと投票が重なったとき、前の票が次の投票に混ざらないようにするため。
- **「タイルを置く」の一覧**: 専用の部品(`MkSpaceTilePicker`)は作らず、メニューで出している。
- **Play のタイルは「大きく出す」ができない**: 大きく出すと動かし直しになり、進み具合が消えるため。
- **右のタブ**: ページの幅が 900px 以上のときに2列になる。それより狭いとき(スマホ、ウィジェットを出している狭い画面)は、通話の下にタブが来る。
- **続きをひらく**: タイルを置ける人の設定(`tilePlacement`)も引き継ぐ。

### 14.2 残っている弱いところ

- **ドライブをオブジェクトストレージに置いている場合、画像のタイルに画像が出ない**。枠が読める画像はこのサーバーの `/files/` の下だけにしてあるため。本番の構成を確かめる必要がある。
- **リンクのタイルは、枠の外へ情報を送る道になりうる**。`space.preview(url)` は本体がその URL を取りに行くので、URL にデータを載せれば外へ出せる。段階3のタイルは本体が用意したものだけなので実害は無い。段階4で自作タイルに開ける前に、利用者の操作があったときだけ動くようにするなどの手当てが要る。
- 担当の決め直しが2つ同時に動くと、まれに担当がいない状態になる(次に人が出入りするまで)。タイマーは上の待ち時間のあとにほかの人が書くので、切れないままにはならない。
- 投票とやることは、値が変わるたびに描き直す。キーボードで操作している途中だと、フォーカスが外れる。
- らくがきはキーボードでは描けない。線が増えると、描くたびに全部を描き直すので重くなる。
- 続きをひらく処理の途中(タイルを写している間)にだれかが入ると、あとから写したタイルがその人に出ないことがある。
