## (2) 残る問題（いずれも P2。実装の妨げにはなりません）

1. **匿名閲覧の証明のキャッシュ単位**
   - L123 は「匿名の証明を匿名セッションとして区別する」としています。
   - 匿名セッションごとに証明を取ると、未ログインの `notes/show`・SSR 1件ごとに相手への署名付き通信が発生し、負荷の増幅経路になります。
   - 匿名の証明は「ルート＋掲載」単位で匿名閲覧者全体に共有し、否定結果のキャッシュと頻度制限を付ける、と明記するのが安全です。
2. **事前認可なしで pack する経路**
   - 次の経路は、まとめての事前認可を通らずに `isVisibleForMe` で判定され、拒否側（本文を隠す側）に倒れます。
     - 通知（専用返信内のメンションなど）
     - ストリーム
     - クリップ・お気に入り
   - 相手側の経路しかない正当な閲覧者には、本文が隠されて届きます。これを意図した挙動とするか、事前認可を行うかを、L129 の適用経路の一覧に加えてください。
3. **専用返信の「来歴」の保存先が保存記録の表（L56-65）にない**
   - L38・L125・L149 は「保存した来歴」を前提にしています。
   - 実際には既存の列（`channelId IS NULL`・`includeDefault=false`・`replyId`・guest の `userId`）と既存の `GridspaceReplyReceipt` から導出できます。
   - 導出で済ませるのか、新しい列を作るのかを一行明記してください。
4. **返信者本人による「返信単体の閲覧」の経路**
   - L125 は、経路を失った後も返信者が自分の返信単体を閲覧・削除できるとしています。
   - しかし操作表（L73-80）と受け入れ条件（L240）には削除しかありません。ホーム側から本人返信を読む操作を追加するか、削除のみとするかを決めてください。
5. **ミラーが恒久的に取り込めない通常原本**
   - `read()` は、投稿者の停止や `makeNotesHiddenBefore`/`makeNotesFollowersOnlyBefore` の条件で `unavailable` を返します（`GridspaceNoteService.ts:89-93`）。
   - このとき掲載は有効なまま、ずっと読み取り専用になります。
   - 掲載経路で本文を取得する際にも、同じ時刻による非表示条件を適用すると L109 に明記してください。
6. **表現の残り**
   - 契約 L111「local 優先の `assertOwners` を修正」と L113「local 優先判定を維持」は、L113 側の限定（直すのは経路集合の部分だけ）で読めますが、L111 に一言足すと誤読を防げます。timeline.md:16 にも同じ補足が必要です（L83 にはあり）。
   - multi-note.md:121 の掲載表の列には、`canonicalUri`・`sortAt`・SET NULL がまだ書かれていません。timeline.md:57 と揃えてください。
