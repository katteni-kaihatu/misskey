### Renote compatibility

An action on an already published channel-only original needs a verified source channel and exactly one destination. The existing production menu has five choices. The two in-channel choices remain available for a readable active source whose channel disallows export. Outside posting and a different channel additionally require the source channel's `allowRenoteToExternal` setting.

The proposed compatibility path identifies the original by canonical URI and the source placement by its channel origin and ID. The original server checks the current conversation read grant. The channel owner checks that the exact placement remains active and authorizes the destination. Write-time checks cover the author, the active source route, its export setting and the destination channel's write and archive rules. The existing conversation write check can succeed through any eligible channel and needs an exact-route check for this purpose.

The existing `gridspaceQuote` field can hold a local-only reference for a pure renote or a comment-bearing quote, preserving one original. Reference parsing and the current-viewer note-link renderer must recognize the scoped form, and legacy references must still resolve. Each action creates an ordinary post or exactly one channel post. A direct detail with several visible placements needs the selected source channel. For an already created reference, its preview follows the current viewer's ability to read the original. Disabling export or removing its last placement stops new actions from that route; an otherwise readable public original still opens by its direct or conversation URL.

#### Agreed action contract

| User action on a published root | Target | Policy | Stored result |
| --- | --- | --- | --- |
| Renote | Ordinary route on the viewer's server | Source allows external renotes | One textless reference note |
| Quote | Ordinary route on the viewer's server | Source allows external renotes | One reference note with the author's comment or media |
| In-channel renote | Exact source channel on its owning server | Source remains active; actor can post to that channel | One textless, single-channel reference note |
| In-channel quote | Exact source channel on its owning server | Same current read/write checks | One single-channel reference note with author-supplied content |
| Renote to another channel | One selected favorite on either server | Source allows external renotes; actor can post to destination | One textless, single-channel reference note |

The source identity consists of the canonical original URI, its server-scoped note ID, and the selected placement's channel origin and ID. Accept only canonical note URIs belonging to these two configured servers, with ID agreement. An origin and channel ID together identify a destination. Preserve the legacy quote format for existing data. For a scoped reference, both servers resolve the original using its canonical origin, even when its storage origin, author's home server, embedded reference URL host and selected channel owner differ.

Use the source channel shown in the timeline when available. In a detail reached by another route, a single active visible placement is unambiguous; ask the reader to choose a source if several are eligible. Only original dedicated roots qualify for this shortcut. Ordinary roots retain their ordinary action path, and conversation-only replies have no channel placement.

The agreed writer uses `notes/create` for both destinations. An outside post contains only the qualified `gridspaceQuote` and uses ordinary creation. An in-channel or cross-channel post uses the same reference, exactly one channel target, `includeDefault=false` and a client request ID. The existing durable receipt and placement pipeline creates one child under the signed-in author. The child's source, destination and content participate in its input hash; the receipt also belongs to that user. A repeated send returns the same child. A reused receipt with different input fails. Both writers force `localOnly`. The canonical original retains its own ID, attachments, reactions and poll.

Test the source checks through the public entry point using an ID/origin mismatch, an unrelated or removed placement, a reader/owner block, export disabled between prepare and send, a destination archive and a duplicate receipt. Verify the resulting single-channel child appears in exactly the selected channel and the outside child uses the chosen ordinary audience. Check that changing roles or visibility hides the source card as appropriate without deleting the author's quote. Verify AP never receives these references. Legacy quote references with placements, two or more destinations, an outside/default route plus a channel, and scheduling remain invalid combinations. The qualified wire format uses the canonical note URL and the exact `gridspaceChannelOrigin` and `gridspaceChannelId` query parameters.

## Independent verification

- On each fork, 13 in-memory assertions exercised its actual receipt-hash function against the old feature implementation and new payloads. Omitted/default relay and quote fields preserve historical hashes. Changing the source note, source channel ID/origin, destination channel ID/origin, content, files, poll, default route or relay option changes the hash.
- On each fork, 18 in-memory assertions executed the actual reference parsers over the four combinations of note and channel owner. They covered invalid or unpaired origins, bad IDs, duplicate/extra parameters, protocol, credentials, fragments and the legacy note/channel reference.
- Inspected the singleton writer and the placement timeline's hydration path. The writer checks the receipt before a fresh source lookup, hashes the canonicalized reference, rejects multiple or mixed destinations and invokes the source check inside the insert transaction. The placement timeline applies the renote filter to native and delegated reference-only children and queries the viewer's renote mutes using local author IDs or canonical peer author URIs. A comment, CW, reply, file or poll distinguishes a quote from a pure renote.
- Inspected the revised note-link resolver. Previously created references retain their preview when their last placement is removed and the current viewer can still read the original. Write checks continue to require the exact active placement and enforce the selected source channel's export policy.

- Verified the R core E2E log at `.config/multi-note-core-scoped-e2e.log` in its worktree. It records 17 passing tests in two suites.
